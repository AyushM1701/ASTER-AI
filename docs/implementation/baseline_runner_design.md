# Controlled offline retrieval experiment runner

Extend the existing Python/NumPy infrastructure without changing installed indexes, public APIs or model settings. Use the same admitted teaching corpus, metadata/hold filtering and a single total candidate budget per question. B0 runs BM25; B2 runs the existing frozen local dense encoder; B3 fuses BM25 and dense ranks with RRF; B5 retrieves independently for subject-bound facets, merging their ranked lists within the same total budget. These are retrieval-stage comparisons: B2/B3/B5 do not become complete generated-answer baselines merely by producing candidates.

B6 uses the same B5 candidates and the existing evidence planner, exact extraction composer and terminal guard. Its experimental teacher contains only the budgeted records and their metadata, preventing direct inspected-binding candidates from escaping the budget. It deliberately excludes prepared explanations from every arm; comparison with the prepared operational pilot is a separate experiment. Safety, rights, holds and applicability remain deterministic.

Every run freezes source files, index/model assets, input cases, relevant code, environment and config. Source/index/input mutation invalidates the run. Output directories are immutable. Labels are optional, explicit and provenance tagged; unlabelled cases receive null retrieval scores. No faculty accuracy, calibration, unseen score or novelty is inferred. B1/B4/B7/B8 remain explicit not-run rows until their audited model and experimental prerequisites exist. This phase closes an executable retrieval/guard harness, not all B0–B8/E1–E15 comparisons.
